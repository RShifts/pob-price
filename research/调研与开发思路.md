# POB 查价工具 — 项目总结与关键记录

> 目标：输入 POB Code/链接，解析构建（装备/药剂/宝石/天赋珠宝），通过官方市集 API 批量查类似装备价格并汇总估值。
> 支持：国际服（pathofexile.com）+ 国服（poe.game.qq.com）。

## 一、架构（管线）

```
POB链接/Code → 解码(zlib+base64) → XML解析 → 物品文本解析(稀有度/基底/词缀/腐化)
                                                          ↓
物品 → 词缀文本→stat id 匹配(官方 data/stats) → 市集查询JSON
                                                          ↓
官方市集 search(2s间隔限流/429退避/磁盘缓存) → fetch 挂牌 → 价格聚合
                                                          ↓
逐项估值(最低/中位/均价) + 市集链接 + CSV
```

## 二、里程碑

- **M1** 解析：POB Code 编解码（zlib+URL-safe base64）、XML 解析（新旧两种布局）、物品文本解析、3 个真实 fixture、node:test 56 用例
- **M2** 单件查价：词缀 stat 匹配（# 占位归一化）、查询构建、API 客户端（限流/429/缓存）、poe.ninja 折算（不可达时混沌 1:1 兜底）
- **M3** 批量引擎：整构建排队查价、去重计数量、宝石查价（Support 后缀）、按品类聚合、总净值、CSV
- **M4** 国服：中英翻译表（4728 条）、Cookie 会话、国服查询结构适配（见下）

## 三、关键踩坑记录（重要）

### 国服（poe.game.qq.com）

1. **必须登录**：搜索接口匿名返回 401；需要 QQ 登录会话 Cookie（POESESSID 等整串）。
2. **status 必须用 "any"**：`status: {"option":"online"}` 会被国服后端静默返回 total:0（不报错）。这是之前"所有查询都 0"的根本原因之一。
3. **不能传 sale_type**：`trade_filters.filters.sale_type`（任何值）也会导致返回 0。
4. 名称必须用中文（国服官方译名，如 双玉戒指 而非 双石戒指）；翻译表已验证与国服数据一致。
5. stat 词缀 id 跨服通用：匹配用国际服英文词缀表，查出的 id 直接用于国服查询。
6. 请求需带 Origin/Host/X-Requested-With/Referer（对齐开源工具 Awakened-PoE-Trade-Simplified-Chinese）。
7. 长 Cookie 含分号：命令行直传会被 shell 拆断，用 --cookie-file 存文件。
8. 国服 listing 的 account.online 可能为 null（价格聚合需可选链）。
9. DPoP/access token 不需要（分叉源码确认纯 Cookie 即可）；--refresh-token/--dpop-token 仅为可选扩展。

### 国际服

- 词缀 stat 匹配：同名词缀存在多个 type 的 id（explicit/implicit/crafted...），AND 过滤只能取一个，否则无解。
- 会话内请求过多会触发 GGG 429（Retry-After 可达数十秒），客户端自动退避；调用间隔默认 2s。
- poe.ninja 在本环境不可达，混沌基准 1:1 兜底。

## 四、技术要点

- Node ≥ 22.6，零运行时依赖（node:test + --experimental-strip-types + .js→.ts 导入钩子 tools/）
- 测试 56 个用例全绿；fixture 来自 pobb.in 与开源仓库的真实构建
- 中英翻译表 src/trade/data/en-cn.ts（生成脚本 tools/generate-translation.mjs）
